## Multi-server upsmon monitoring (post-sync feature work)

Added after the template sync, at your request: a host can now monitor any
number of remote NUT servers, each with its own credentials, independent of
(and in addition to) a locally-driven UPS. This replaces the unreleased,
single-host `nut_upsmon_ups_name` mechanism that predated this session
(folded in / removed, per your decision).

* `defaults/main.yml` — added `nut_upsmon_monitors: []` (list of dicts:
  `name`, `host`, `user`, `password` required; `port`, `role`,
  `powervalue` optional, with `role`/`powervalue` falling back to
  `nut_upsmon_role`/`nut_powervalue`). Removed the unused
  `nut_upsmon_ups_name` placeholder.
* `templates/upsmon.conf.j2` — rewrote the MONITOR block: one line per
  `nut_ups` entry (local driver) plus one line per `nut_upsmon_monitors`
  entry (remote), so both can coexist.
* `tasks/preflight.yml` — added a required-field assert over
  `nut_upsmon_monitors` (`name`/`host`/`user`/`password`), `no_log: true`,
  labeled loop per existing convention. Also fixed the `nut_users` fail_msg
  wording nit flagged below ("Offending entry index:" → "...name:").
* `meta/argument_specs.yml` — documented `nut_upsmon_monitors` and its
  sub-options.
* `README.md` — UPSMON table row updated; "Netclient" example rewritten to
  use `nut_upsmon_monitors` (single entry) instead of the removed
  `nut_upsmon_ups_name`; added a new "Multi-server monitoring" section with

  servers, mirroring your Synology1/Synology2/PVE-02 topology).
* `molecule/default/converge.yml` — added a 3-entry `nut_upsmon_monitors`
